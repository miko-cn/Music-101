# Music-101 课程改造 v2：记忆锚驱动的教学路线

- 日期：2026-10-25
- 状态：已实现（阶段一全量重写 + 阶段二/三扩容 + 全局参考键盘）
- 依据：`docs/superpowers/specs/2026-10-20-music-101-design.md` + Open Music Theory v2（CC BY-SA 4.0）

---

## 1. 出发点（不变）

这是给**乐理零基础**的人用的业余编曲速成站：

| 维度 | 情况 |
|---|---|
| 乐理基础 | 基本为零（看得懂"和弦"这个词，但不会算级数、不会看谱） |
| 目标 | 写自己的原创歌曲，**器乐 BGM 为主**（蔚蓝档案风格），后期可能加虚拟歌姬 |
| 目标风格 | kawaii bass / future bass（明亮、可爱、躁动） |
| 工具 | Cubase 13 + Studio One 5；**无 MIDI 键盘、无乐器、无录音设备** |
| 每天可投入 | 15–30 分钟碎片时间 |
| 目标产物 | 2–3 个月内独立编出结构完整、听感像样的器乐曲，**并且知道为什么这样编** |

这次改造只动**课程层**（内容、练习结构、记忆机制），不动技术架构、不动诊断引擎、不动 MIDI 导出链路。

## 2. 问题诊断

原始 24 关的实际形态（对照 `40d713a`）：

| 问题 | 证据 | 后果 |
|---|---|---|
| 每关内容量太少 | 概念讲解共 50 段、2301 字，摊到 24 关 ≈ 每关 2 段 / 96 字 | 达不到设计规格承诺的 15–20 分钟，实际每关 5–8 分钟 |
| 没有记忆点 | 全课程 **0** 个记忆锚、0 条口诀、0 条判定流程 | 学完只剩零散事实，无法自己复述，也不会迁移 |
| 听辨练习信息量低 | 86 道题全部是**二选一**，平均选项数 2.00 | 二选一只能练「辨别」，练不出「辨认」；且容易形成答题习惯而非听觉能力 |
| 教学法不成体系 | 每关只有「概念 → 听辨 → 手做 → 诊断」四步，没有复述、没有提取练习、没有复习 | 间隔一周回来等于没学 |

## 3. 教学路线

### 3.1 记忆锚三件套

借鉴 Open Music Theory v2 每章开头的 **KEY TAKEAWAYS** 结构，以及它对「判定流程」的偏好（教材明确说判定音程性质**不要用数半音的方法**，要用"主音想象法"——因为流程可以自己走一遍，结论不能）。

每一关现在必须挂一个**记忆锚**（`src/content/anchors.ts`）：

| 组成 | 作用 | 例（关 3） |
|---|---|---|
| `hook` | 能背下来的那一句 | 「把低音当成主音，上音在大调里就是标准性质。」 |
| `steps` | 能自己走一遍的判定流程（≥3 步） | ① 数大小（第一个音算 1）② 低音想象成大调主音 ③ 看高音在不在这个大调里 ④ 定性质 |
| `takeaway` | 带走这一关的结论清单（≥3 条） | 「数大小第一个音算 1，而且按音名数」等 |

**为什么口诀和流程都要有**：口诀负责「想起来」，流程负责「用出去」。只有口诀，遇到没背过的情况就废；只有流程，记不住就无从启动。

### 3.2 练习递进

每一关固定走六步（与设计规格 §3.2 的模板对齐）：

```
概念卡（含记忆锚） → 听辨 → 手做 → 诊断 → 记忆点（锚 + takeaway + 过关标准） → 导出
```

「记忆点」是**新增的第 5 步**，独立于「诊断」。理由：诊断解决「我这关过没过」，记忆点解决「这关我记住了什么」。过关后还能再看一眼口诀和 takeaway。

### 3.3 消除答题位置偏差

原实现里正确项**永远排在第 0 位**（`ear()` helper 固定构造）。这会让学习者形成「永远选第一个」的肌肉记忆，听辨能力练不出来。

现在 `ear()` 按声明顺序轮转正确项位置（`earSlot++ % 3`），并由测试 `正确项不在每题都排第一` 守住上限。

### 3.4 复习钩子

每关声明 `prereq`（前置关卡）。记忆点步骤会显示「这一关的地基是第 X、Y 关」，卡住时知道该回去补哪一关。守卫测试确保 `prereq` 只指向**更早**且**确实存在**的关卡。

## 4. 数据模型变更

```ts
// src/content/anchors.ts（新增）
export interface MemoryAnchor {
  id: string;        // 锚点代号，如 "tonic-imagine"
  name: string;      // 锚点名字，如 "主音想象法"
  hook: string;      // 一句话口诀
  steps: string[];   // 判定流程
  takeaway: string[];// KEY TAKEAWAYS 风格的结论清单
}
export const ANCHORS: Record<number, MemoryAnchor>;  // 24 关全覆盖

// src/content/stage1.ts
export interface StageLesson {
  // ...原有字段
  anchor: MemoryAnchor;   // 必填 —— 没有记忆点的关卡不允许存在
  prereq?: number[];      // 复习钩子
}
```

`anchor` 设为**必填**，配合 `lesson()` helper 自动从 `ANCHORS` 取值，编译期就保证每关都有记忆点——这是比文档约定更硬的约束。

## 5. 记忆锚点清单

| 关 | 主题 | 记忆锚 | 口诀 |
|---|---|---|---|
| 1 | 音高与键盘直觉 | 黑键 2-3 分组 | 两黑键一组，三黑键一组；C 在二组左边，F 在三组左边 |
| 2 | 半音与全音 | 相邻键法 | 半音是隔壁，全音隔一个 |
| 3 | 音程与协和度 | 主音想象法 | 把低音当成主音，上音在大调里就是标准性质 |
| 4 | 大三 / 小三和弦 | 三度堆叠法 | 和弦是三度叠起来的，性质只看中间那个音 |
| 5 | 音阶与调 | 五度圈 | C 在 12 点，顺时针加升号，逆时针加降号 |
| 6 | 七和弦与色彩 | 根三五七 | 七和弦就是三和弦上面再叠一个三度 |
| 7 | I–V–vi–IV | 罗马数字大小写 | 数字是第几级，大写小写是大三还是小三 |
| 8 | 小调与借用 | 以大调为尺子 | 小调是拿同名大调当尺子，差半音的级数加 ♭ |
| 9 | 织体：什么是层 | 轨道即层数 | 层按轨道数算，不按音符个数算 |
| 10 | 鼓组四件套 | 强拍归踢，反拍归军鼓 | 踢占强拍，军鼓拍手占反拍，踩镲铺八分 |
| 11 | 808 与 kick 分工 | 长短分工 + 低频不重叠 | kick 管冲击，808 管根音；两者别挤在同一段低频 |
| 12 | 侧链泵动 | 跟 kick 走 | kick 一响就按下去，kick 一走就抬回来 |
| 13 | 段落与能量曲线 | 1.5 倍 + 1 层 | 抬层要同时满足：能量 1.5 倍，层数多 1 |
| 14 | 和声张力与解决 | V 要落到 I | 属和弦想回家，落到主和弦张力才落地 |
| 15 | 音色角色与频段 | 从低到高排队 | kick 最低，贝斯次低，和弦再往上——各占一段 |
| 16 | 厚度 | 拉开八度 | 同一个音名，差一个八度一起响，才有厚度 |
| 17 | 动态 | 力度差 = 呼吸 | 主歌收着，副歌推上去，全程一样就是不呼吸 |
| 18 | 效果 | 效果用在转折处 | 效果负责接段落，不是从头糊到尾 |
| 19 | Future bass 骨架 | 副歌加锯齿 | 主歌留 kick + 贝斯，副歌铺 supersaw，短 chop 卡反拍 |
| 20 | Kawaii bass 声音特征 | 亮、轻、颗粒 | 和弦用大七或加九，拍手靠前，和弦抬到高八度 |
| 21 | Vocal chop 入门 | 碎片卡空拍 | 短音切片，落在正拍之间的空位 |
| 22 | 副歌抬一层 | 加轨 + 1.5 倍 | 主歌留两层，副歌加一条 supersaw，能量到 1.5 倍 |
| 23 | 从零编 16 小节 | 16 小节 = 4 + 4 + 8 | 前奏 4、主歌 4、副歌 8，副歌多一条 supersaw |
| 24 | 参考曲分析 | 候选式分析 | 不追求一次猜对，从候选里选最像的 |

## 7. 守卫测试

新增 `tests/lesson/curriculum.test.ts`（8 项），把上面这些标准固化成测试，防止内容质量回滑：

1. 24 关全部配了记忆锚，锚点 id 无重复

## 8. 全局参考键盘（配套设施）

学习者没有实体 MIDI 键盘、没有乐器、没有录音设备，只看音符名字太抽象——「C 在哪个键上」没有具现化的依托。这是课程之外的第二个痛点，单独立一个全局设施解决（提交 `209c7ca`）。

### 8.1 做了什么

`src/ui/KeyboardPanel.tsx` 是一个 antd Drawer，header「键盘」按钮或全局快捷键 **K** 随时呼出，不塞进关卡步骤——它是查位置的工具，不是一次练习。

| 能力 | 说明 |
|---|---|
| 多八度铺开 | 2 / 3 / 4 个八度；黑键「2 个一组、3 个一组」的重复规律一眼可见 |
| **C4 在正中间** | 布局以中央 C 为中心向左右展开，不是「从某个 C 开始铺」——打开就能当尺子用，不用先找 C4 才知道往哪边数 |
| 音名标注 | 每个键都印音名（**黑键也印**），可单独开关 |
| MIDI 编号 | 可选叠加，和 Cubase / Studio One 里的编号直接对上 |
| 2-3 分组标记 | 顶部标出每组黑键的「2 个 / 3 个」，底部标出 C 和 F 两个定位点 |
| 找这个音 | 选一个音名，所有八度的同名键同时高亮，并列出各自的 MIDI 编号 |
| 听一个音，自己找 | 听到一个音后自己在键盘上点，对错立刻反馈，可「再听一次 / 换一个」 |
| **按住发声、松手制音** | 延音由手指按多久决定，不留固定时长的回声（见 §8.4） |
| **记谱渲染** | 音名用衬线体 + ♯/♭ 记谱符号 + 下标八度，一眼能和正文分开（见 §8.5） |

### 8.2 两条不能破的规矩

1. **测验未作答时键盘上一个键都不能高亮。** 高亮等于把答案直接说出来，测验就废了。
   判定逻辑抽成 core 层纯函数 `quizHighlight()`，由 `tests/theory/keyboard.test.ts` 守住这条规则。
2. **作答之后才标位置**：正确的那一个键（精确到 MIDI 音高）标红，同名音标金——既是判分，也是复习「同名音每高八度加 1」。

### 8.3 为什么布局逻辑要抽成纯函数

`src/core/theory/keyboard.ts` 的 `centeredKeyboardLayout()` 不碰 DOM，可以直接单测。这一点是有代价换来的：初版用 `base + offset + 1` 算黑键音高，结果每个八度的 5 个黑键音名全错（`C#2, D2, E2, F2, F#2`——全是白键音高），画进界面后学习者会照着记错位置。

后来又换了两次算法，两次都只靠肉眼看截图看不出来，所以测试必须跟上：

- **黑键改成从白键间距推导**（相邻白键差全音才夹黑键），不再依赖「起始音必须是 C」。这样居中布局的边缘才画得对。
- **「2-3 分组」也改成从黑键实际位置推导**（相邻黑键差 2 个半音算一组），不再写死「每八度第 1、4 个白键是 C、F」。3 个八度居中时左端是 G2，边缘那半组 `G#2 A#2` 照样该标「2 个」。

**教训：会把音高/位置画给学习者看的东西，算法必须能单测，不能靠肉眼看截图。**

### 8.4 延音必须跟住按住时长

初版键盘点一下就按固定时长（1.6 秒）响完，学习者松手之后余音还在继续——听感就是「回声很大」，而且点得越多叠得越脏。

改法是把电钢音拆成两段（`src/core/audio/engine.ts`）：

- **起音 + 自然衰减**（`startPiano`）：敲下去那一刻发生，高次泛音先死，这段跟按住多久无关。
- **制音器**（`dampVoice`）：松手那一刻落下，把泛音快速掐掉。

引擎新增 `pressPitch(midi) -> voiceId` 和 `releasePitch(voiceId)`，界面用 pointerdown / pointerup 配对（并用 `setPointerCapture` 抓住指针，手指滑出琴键也不会漏掉松手）。

两个细节：

1. **制音器不能早于起音**（`DAMPER_MIN_SECONDS = 0.12` 秒）。真实钢琴的毡垫落下去要走一点时间，少了这个下限，快速点一下就变成「咔」的一声，听不见音高。
2. **按下必须同步完成**。如果 `pressPitch` 前面挂着 `await`，「快速点一下」会在松手之后才起音——所以 `press` 里不 await 引擎恢复，只把 `resume()` 丢成后台 promise。

### 8.5 音名要用记谱写法，不能用正文的字体

用正文的 sans 字体写 `C#4`，学习者分不清那是音名还是普通词；而且 `C#` 的 `#` 长得像代码，不像降号。

**分层**（详细见设计规格 §3.8）：

- `core/theory/pitch.ts` 保持 ASCII——要能解析回来，导出的 MIDI 标记（`F#m (i)`）也要跟 Cubase 对得上。
- `core/theory/notation.ts` 负责转成谱面写法：♯ ♭ 𝄪 𝄫。
- `src/ui/NoteName.tsx` 负责渲染：衬线体字母 + 记谱字体的变音记号 + 下标八度。
- 字体：自托管 Noto Music 音乐符号子集（56KB，SIL OFL 1.1），`unicode-range` 限死职责，字母自动落到衬线体。

**踩过的坑**：JS 里 `"\u1D12A"` 是 `"\u1D12"` + 字母 "A"——四位转义不支持星平面字符。
必须写 `"\u{1D12A}"`，正则还要加 `u` 标志。`tests/theory/notation.test.ts` 用码位断言守这一条。

**变音记号不能只靠基线对齐**：记谱字体的 ♯ ♭ 是按五线谱位置画的。升号横跨谱线、重心在基线以下，
并排显示要往上提（`top: -0.12em`）；降号的碗坐在基线上，提了就浮起来（`top: -0.02em`）。
另外整体放大到 1.3em、加 0.02em 描边——雕刻线在正常缩放下只剩半像素，会淡成一抹灰。

## 9. 后续可做（本次未做）

1. **间隔复习队列**：利用已有的 `core/lesson/progress.ts` 错误画像数据，按 Leitner 盒安排「该复习哪一关」，把 `prereq` 变成真正的调度逻辑，而不只是提示文字。
2. **记忆点总表页**：24 个锚点已集中在 `ANCHORS`，可以直接渲染成一页速查表。
3. **提取练习（retrieval）**：把 takeaway 变成「合上卡片复述」的自测，而不是只读。
4. **阶段二/三 的和声内容仍偏薄**：关 9–24 目前以编曲决策为主，和声学只覆盖到 I–V–vi–IV 与 i–♭VI–♭III–♭VII。若要进一步支撑「知道为什么这样编」，需要补和声功能、终止式、转调三块。
5. **键盘测验接进进度**：目前「听一个音，自己找」只是一个独立练习工具，答错不进入错题画像。可以把它写进 `core/lesson/progress.ts`，让「音高定位」成为一个可跟踪的薄弱项。
6. **键盘面板的窄屏布局**：当前 Drawer 固定 880px，手机上需要横向滚动才能看全 4 个八度。

# Music-101 设计规格：kawaii bass / future bass 编曲速成

- 日期：2026-10-20
- 状态：已批准（2026-10-20）
- 作者：PI-Desktop（brainstorming 阶段产出）

---

## 1. 背景与目标

### 1.1 学习者画像

| 维度 | 情况 |
|---|---|
| 乐理基础 | 基本为零（能看懂"和弦"这个词，但不会算级数、不会看谱） |
| 目标 | 写自己的原创歌曲，**器乐 BGM 为主**（蔚蓝档案风格），后期可能尝试虚拟歌姬（VOCALOID 类）作为人声 |
| 目标风格 | kawaii bass / future bass（明亮、可爱、躁动） |
| 现有工具 | Cubase 13（`D:\Production\Cubase 13\Cubase13.exe`）、Studio One 5（`D:\Production\Studio One 5\Studio One.exe`） |
| 缺的工具 | 无 MIDI 键盘、不乐器、不录音设备 |
| 每天可投入 | 15–30 分钟（碎片时间） |
| 学习形式偏好 | 主线闯关 + 随时可进沙盒（混合） |

### 1.2 产品目标

让一个乐理零基础的人，在**每天 15–30 分钟**的节奏下，**约 2–3 个月**内，能独立编出一首结构完整、听感像样的 kawaii bass / future bass 器乐曲，并且知道**为什么**这样编。

### 1.3 非目标（明确不做）

- 不做完整 DAW。网页端不提供自由手绘音符的时间轴。
- 不做虚拟歌姬 / 人声合成引擎。虚拟歌姬在 Cubase 内挂插件完成。
- 不做账号体系、后端服务、云端渲染。
- 不使用任何第三方受版权保护的音频素材（含《蔚蓝档案》原始音频）。
- 不做移动端专门优化（响应式可用即可，桌面优先）。
- **不做与 Cubase 的直接集成**（不读工程状态、不下指令、不依赖驱动）。网站与 Cubase 之间只通过 MIDI 文件交换。Agent 直接操作 Cubase 的能力（第 5 节 L3）属于 Agent 侧工具，独立交付，与网站无关。

## 2. 核心架构决策

### 2.1 方案选型

评估了三条路线：

| 方案 | 内容 | 结论 |
|---|---|---|
| A | 网站只做理论课，练习全在 Cubase | 工程量最小，但无即时反馈，学习闭环断裂 |
| B | 网站自建完整轻量 DAW | 即时反馈好，但重造时间轴（拖拽/吸附/缩放/框选/撤销）成本最高，且永远不如 Cubase |
| **C′（采用）** | 网站做「教 + 听 + 决策 + 诊断 + 骨架生成」，时间轴交给 Cubase | **采用** |

**C′ 的关键判断**：唯一需要"手绘轨道"的地方是网页时间轴，而那正是被砍掉的部分。砍掉之后：

- 精度问题消失——MIDI 是整数 tick 定位，无浮点漂移
- 工程量节省最大
- 学到的直接是 Cubase 真本事（用户本来就有 Cubase）
- 碎片时间在网页学，进 Cubase 只需几分钟做决策 + 精修

### 2.2 职责划分

| 组件 | 承担 | 不承担 |
|---|---|---|
| **Music-101 网页** | 交互式乐理教学、听辨训练、实时合成试听、决策式任务、16 格步进器、参考曲分析、诊断引擎、MIDI 骨架生成 | 自由时间轴编辑、最终成稿 |
| **Cubase 13** | 时间轴、编辑、量化、Automation、Chord/Scale 轨、采样与混音、虚拟歌姬、最终成稿 | 教学、听辨训练、即时诊断 |
| **Agent 侧工具（可选，独立于网站）** | 直接读 Cubase 工程状态、直接操作 Cubase（协作场景下代替人工点击） | 教学、课程内容 |
### 2.3 学习闭环

```
STEP 1  做决策      网页内选和弦 / 选鼓型 / 排段落；16 格步进器打节奏
STEP 2  试听 + 诊断 网页实时播放，给出「和声在调内」「副歌没抬层」等具体提示
STEP 3  导出骨架    生成 tick 级精确的 .mid（tempo map / 段落 marker / 轨名 / 和弦轨）
STEP 4  拖进 Cubase 用户在此做真正的创作：音色、细节、Automation
STEP 5  导回 MIDI   Cubase 导出 → 拖回网站
STEP 6  网站读懂    分析和声进行、能量曲线、频段冲突，给出下一步建议
```

STEP 3→4 的精度由 MIDI 格式保证；STEP 5→6 的信息损失限于 Cubase 导出时不携带的图形/自动化数据，和声与时值无损。

**两条路径的区分**：

- **产品路径**（学习者独自练习，Agent 不在线）：STEP 1→6 完整走一遍，网站必须自洽可用。导回 MIDI 是唯一的跨应用通道。
- **协作路径**（学习者与 Agent 一起做一首歌）：Agent 通过第 5 节的 Agent 侧能力直接读 Cubase 状态、直接操作 Cubase，跳过导出拖回。此时网站退化为"教 + 试听 + 生成骨架"的辅助。

两条路径共用同一套参数语义与同一套诊断规则，因此网站里练熟的东西在协作时同样成立。

## 3. 功能规格

### 3.1 课程体系：24 关主线

### 3.2 单关结构模板

每关 15–20 分钟，六步固定：

1. **概念卡** — ≤90 秒读完的短文 + 键盘图示
2. **耳朵任务** — 约 5 道听辨选择题，答错立刻解释为什么
3. **手做任务** — 决策式交互（选和弦 / 选鼓型 / 排段落）；节奏类关卡用 16 格步进器
4. **即时诊断** — 对错 + 原因 + **可点击的修正建议**
5. **导出到 Cubase** — 本次练习转为 MIDI 骨架，下载拖入即可用
6. **过关标准** — 可量化判定（例：副歌能量 ≥ 主歌 + 2 层；全部和声在调内）

### 3.3 诊断引擎

全部为**确定性规则**，不依赖 AI 推断。输入 MIDI 事件流或决策状态，输出 `Diagnostic[]`（含严重度、定位到小节、可选修正动作）。

| 诊断项 | 判定方式 |
|---|---|
| 和声归属 | 音高集合匹配和弦模板 → 每小节级数归属 → 是否在调内 |
| 能量曲线 | 每小节统计 `层数 × 音区 × 力度` → 折线 → 副歌是否抬层 |
| 低频冲突 | Kick 与 808 sub 音高区重叠检测 |
| 频段占位 | 各轨频率重心 → 是否挤在中频互相打架 |
| 结构体检 | 小节数 / 段落 marker / 循环重复度 → 定位"第 N 小节起失去新鲜感" |
| 和弦色彩重复度 | 相邻小节和声色彩相似度 → 定位具体小节 |

#### 3.3.1 量化口径定义

诊断与过关标准依赖以下几个可计算量，全部在 `core/analyze` 中有唯一定义：

| 量 | 定义 |
|---|---|
| **层（layer）** | 某小节内**同时发声的轨道数**（同一轨内多个音符只算 1 层；不含 FX 与 CHOP 这类装饰性轨道） |
| **小节能量** | `层数 × 音区权重 × 平均力度`。音区权重：最低音 `< 60`（低频区）记 1.0，`60–79` 记 0.6，`≥ 80` 记 0.4 |
| **"抬一层"** | 副歌小节的平均小节能量 **≥ 主歌平均值 × 1.5**，且副歌层数 **≥ 主歌层数 + 1**，两者同时成立才算抬层成功 |
| **16 格步进器** | 一格 = 一小节内的 1 个 16 分音符。默认显示 1 小节（16 格），可切到 2 小节 / 4 小节视图；每格可选开/关，**不存在拖拽定位**，因此天然无精度问题 |
| **在调内** | 该小节所有音符的音级全部落在目标调的调内音阶集合内；`♭VII` / `iv` 等借用和弦在关卡 8 之后视为合法 |
| **低频冲突** | 808 轨的最低音 `< 45Hz`（MIDI 音高 < 33）**且** 与 kick 轨音符在同一小节内出现 |
| **和弦色彩重复度** | 相邻两小节的音高集合 Jaccard 相似度 `> 0.75` 记为一次色彩重复 |

这些阈值是**首版默认值**，集中定义在 `core/analyze/thresholds.ts`，便于后续按实测调整而不动规则逻辑。


**诚实边界**：听辨任务本质是"选哪个更像"，因此设计为**选择题 + 参考答案的解释**，由学习者判断，不由系统猜。系统只对可计算的部分（音高集合、时值、频谱）作判定。

### 3.4 "定制化"的具体含义

| 机制 | 行为 |
|---|---|
| 错误画像 | 统计反复出现的错误（老用 I–V–vi–IV / 副歌不抬层 / 808 抢 kick），下一阶段自动插入针对练习 |
| 关卡推荐 | 已掌握的直接跳过；诊断不通过的关卡可重开，不卡死进度 |
| 个人配方库 | 每关攒下的和声 / 鼓型 / 音色组合存为"配方"，一键复用，累积成个人风格 |
| 进度仪表 | 按能力维度（和声 / 节奏 / 配器 / 结构）给雷达图 |
| 难度自适应 | 连续 3 次轻松过关 → 变难；连续 2 次卡住 → 插入前置复习 |

### 3.5 声音引擎

纯 Web Audio API 合成，**不使用任何采样文件**（零体积、零版权、零加载等待）。

**输入方式**：电脑键盘映射（`A`–`K` 弹音，`Q`/`W`/`E` 换八度）+ 鼠标点击琴键 + 触屏。**全程零硬件依赖**，不接入 MIDI 设备。


| 积木 | 合成方式 |
|---|---|
| 电钢 RHODES | 加法合成：4 个泛音各自指数衰减（高次泛音先死）+ 弦的不谐和 + 槌击噪声。点琴键、试听用 |
| 纯音 PLAIN | 正弦主音 + 8% 八度泛音。听辨题专用：把音色剥掉，只留音高 || KICK | 正弦 + 音高包络（60→40Hz）+ click 瞬态 |
| 808 | 正弦 + 长音高包络 + 饱和失真 |
| BASS | 锯齿 / 方波 → 低通 → 波形整形失真 |
| SUPERSAW | 7 路失谐锯齿叠加 → 低通 |
| PLUCK / ARP | 短衰减锯齿 |
| CHOP | FM 合成拟人声 "ah"，再做切片 |
| FX | 噪声 + 带通扫频（riser / downlifter） |
| 侧链 | GainNode ducking 自动化（真侧链，非拟态抽吸） |

**参考音分两种，用途不同**（2026-10-25 定）：

- **电钢**是「音乐性」的参考音。点琴键、试听、步进器都用它。学习者需要把「C4」和一段真实的声音绑在一起，
  之后在 Cubase 里换任何乐器都能对得上。
- **纯音**是「分析性」的参考音。听辨题只问音程和和弦性质，答案只跟音高有关；
  有泛音的音色会让人把「音色像」误听成「音高近」，所以这里刻意剥掉。

**听辨题的和弦必须同时响，旋律必须依次响**。和弦题（三和弦、七和弦）听到的应该是和弦本身，
不是它的分解；音程题和音阶题听到的应该是先后出现的音。这条由 `core/audio/ear.ts` 判定，
并由 `tests/audio/ear.test.ts` 对全部 24 关的听辨选项做守卫。

**延音跟住按住时长**（2026-10-25 定）。电钢音拆成两段：**起音 + 自然衰减**（敲下去那一刻发生，
高次泛音先死）与**制音器**（松手那一刻落下，把泛音快速掐掉）。引擎提供
`pressPitch(midi) -> voiceId` / `releasePitch(voiceId)`，界面用 pointerdown / pointerup 配对。

初版是「点一下按固定时长响完」，学习者松手后余音还在继续——听感就是回声，且点得越多叠得越脏。
制音器有 `DAMPER_MIN_SECONDS = 0.12` 秒的下限：真实钢琴的毡垫落下去要走一点时间，
少了它快速点一下就变成「咔」的一声，听不见音高。

**参数复用的诚实边界**：网页合成器与 Cubase 内的 Vital / Serum 等插件**音色不会完全一致**。因此"配方"复用的是**参数语义**（例："808 占据 40–60Hz 低频，kick 走 punchy click 瞬态"），不是音色文件本身。关卡文案需明确说明这一点，避免学习者产生错误预期。

### 3.6 参考曲分析

用户上传本地音频文件，**全程浏览器内处理，不上传服务器**：

1. `decodeAudioData` 解码 → 离线 FFT
2. onset 检测 → BPM
3. chroma 特征 + Krumhansl-Schmuckler 模板 → 调性
4. 和弦识别 → 和弦进行
5. 能量曲线 → 段落结构

输出：结构骨架（段落 + 小节数 + 和弦进行 + 能量曲线），可作为关卡 24 的教材，也可直接生成 MIDI 骨架。

### 3.7 MIDI 导出

- 单轨 `.mid` 或多轨打包 `.zip`
- 精确 tempo map（含变速时用 tempo 事件序列）
- 段落 marker（Intro / Verse / Pre / Chorus / Drop / Outro）
- 轨名与轨序固定为：`KICK` / `808` / `BASS` / `SUPERSAW` / `CHOP` / `ARP` / `FX`
- 打击乐轨用 General MIDI 鼓组映射（kick=36, snare=38, clap=39, closed hat=42, open hat=46）
- **段落与和弦标记**：都用 meta `0x06`（Marker）写入，文本形如 `Intro` / `F#m (i)`
- **meta `0x06` 的冲突（实现阶段发现，已定方案）**：SMF 标准中 `0x06` 是 **Marker**，而 MMA 扩展把 `0x06` 也用作 **Chord Name**，两者共用同一 meta type，在同一文件里无法无歧义地区分。因此**首版只写 Marker，不写 Chord meta 事件**；和弦信息由 `CHORDS` 音符轨承载（每小节一个三和弦的三个实际音高），和弦名以 marker 形式标注
- MMA Chord Name 事件在 Cubase 13 的兼容性留到 M5 单独验证（届时产出一个只含和弦事件的独立文件做隔离测试）

### 3.8 音名的记谱渲染（2026-10-25 定）

音名不只是文本，它是**要学的东西**。用正文的 sans 字体写 `C#4`，学习者分不清那是音名还是普通词。

**数据层保持 ASCII，显示层换成记谱写法。** 这条边界不能破：

- `core/theory/pitch.ts` 继续产出 `C#4` / `Eb2`——它要能被 `noteNameToMidi()` 解析回来，
  而且 Cubase / Studio One 里显示的也是这一套，导出的 MIDI 标记文本（`F#m (i)`）更是必须跟 Cubase 对得上。
- `core/theory/notation.ts` 负责把 ASCII 音名转成谱面写法：升号 ♯、降号 ♭、重升 𝄪、重降 𝄫。
- `src/ui/NoteName.tsx` 负责渲染：字母用衬线体、变音记号用记谱字体、八度数字做成下标。

**字体**：自托管 Noto Music 的「音乐符号」子集（`public/fonts/noto-music-symbols.woff2`，56KB，SIL OFL 1.1）。
`unicode-range` 把它的职责限死在音乐符号上（U+2669–266F、U+1D100–1D245），
字母和数字不在这个范围里，自动落到后面的衬线字体，互不干扰。自托管而不是走 CDN：整个应用零外部请求。

**为什么用下标写八度**：谱面就是这么标的（C₄），而且它把「音名」和「数字」在视觉上分成了两件事。

**变音记号不能只靠基线对齐**（2026-10-25 补）。记谱字体的 ♯ ♭ 是按五线谱位置画的，不是按文字基线画的，
所以升号和降号要分别处理：

| 符号 | 记谱字体里的位置 | 并排显示时怎么处理 |
|---|---|---|
| ♯ / 𝄪 | 横跨谱线，重心在基线**以下** | 往上提（`top: -0.12em`），否则像掉下去了 |
| ♭ / 𝄫 | 碗就坐在**基线**上，柄往上长 | 不能提（`top: -0.02em`），一提就浮起来了 |

另外两点：

- **整体放大到 1.3em**。记谱符号的笔画是雕刻线，跟同尺寸的字母比会细成一根发丝；放大同时也把笔画撑粗了。
- **加 0.02em 描边**（`-webkit-text-stroke`）。正常缩放下雕刻线只剩半像素，会淡成一抹灰。

**判定规则上的坑**（已踩）：JS 里 `"\u1D12A"` 会被解析成 `"\u1D12"` + 字母 "A"——四位转义只支持 BMP。
星平面字符必须写 `"\u{1D12A}"`，正则也要加 `u` 标志。`tests/theory/notation.test.ts` 用码位断言守这一条。

## 4. 技术架构

### 4.1 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite | 快、零配置 |
| 框架 | React + TypeScript | 内容驱动的多视图应用，类型安全对音高/时值数据很重要 |
| 音频 | **原生 Web Audio API** | 需要精确的 tick 调度和真侧链；Tone.js 的抽象层反而碍事 |
| MIDI 读写 | **自研**（约 300 行，零依赖） | 需要精确控制 tick / meta 事件；round-trip 可测 |
| ZIP 打包 | fflate | 轻量，纯前端 |
| 持久化 | localStorage | 无后端、无账号、零运维 |
| 音频分析 | 自研（FFT / onset / chroma） | 避免大依赖 |
| 测试 | Vitest | 覆盖 theory / midi round-trip / 诊断规则 |
| 部署 | 纯静态（GitHub Pages 或 Vercel） | 无服务端 |

### 4.2 模块边界

全部 `core/` 模块为纯函数，不接触 DOM 与 Web Audio，因此可单测、可复用。

```
core/theory     音高·和弦·级数·音阶·调           纯函数
core/midi       MIDI 读写 / 打包                  纯函数
core/analyze    诊断规则 → Diagnostic[]          纯函数
core/audio      合成引擎                          唯一接触 Web Audio 的模块
ui/*            React 组件
content/        关卡内容（JSON）
```

### 4.3 数据流

```
关卡 JSON → 任务 UI → 决策状态 → core/analyze → Diagnostic[] → 修正建议
                                     ↓
                              core/midi → .mid / .zip 下载 → 拖入 Cubase
```

### 4.4 状态持久化

`localStorage` 单键存 `{ progress, errorProfile, recipes, radar, lastSession }`，带 schema 版本号，升级时做迁移。**不上传任何数据。**

## 5. Cubase 13 集成

### 5.1 集成方式

| 层次 | 方式 | 归属 | 说明 |
|---|---|---|---|
| L1（主链路） | **MIDI 文件** | 产品 | 内容生产的唯一通道。tick 级精确，零依赖 |
| L2（辅助） | **cua-driver GUI 自动化** | Agent 侧 | 看屏幕 + 代替点击，像人一样操作。像素级、脆弱，仅用于粗活 |
| L3（可选） | Cubase **MIDI Remote API (Lua)** + 虚拟 MIDI 端口 | Agent 侧 | 结构化读 Cubase 状态 + 精确执行 Cubase 动作。**不做成网站功能** |

**L3 明确不是网站功能。** 它是给 Agent 用的工具，做成 PI-Desktop 插件 + skill 交付，网站完全不知道它的存在。这带来三个好处：网站保持纯静态、无驱动依赖；能力可被任何项目复用；它坏了也不影响产品。
### 5.1.1 L3 的技术路线（已核实）

```
[Cubase MIDI Remote Lua 脚本]
  写：把宿主动作绑成 MIDI 消息 → 虚拟端口 → Agent 触发（执行 Cubase 命令、选轨、走带）
  读：把宿主参数（Song Position、选中轨等）绑成 CC → 虚拟端口 → Agent 接收
      （"光标处的和弦"这类非宿主参数读不到，用 MIDI 导出补）
```

**已核实的关键事实**：

- Cubase 13 自带 **MIDI Remote API v1**，含 141KB TypeScript 类型定义，位于 `D:\Production\Cubase 13\midiremote_factory_scripts\.api\v1\midiremote_api_v1.d.ts`
- 安装目录下 `midi port enabler\enableemulated` 与 `ignoreportfilter` 是 **0 字节标志文件**；创建它们可以让 Cubase 放行**模拟（虚拟）MIDI 端口**并关闭端口过滤
- API 提供 `MR_TrackSelectionAction`（选轨）、`MR_DeviceMidiOutput`（回传数据）、`MR_ActiveDevice` / `MR_ActiveMapping`（读当前映射）
- **本机目前没有任何 MIDI 设备，也没有虚拟 MIDI 端口驱动**，需另装（如 loopMIDI）。安装类操作需单独征得用户同意

**能力边界（诚实说明）**：MIDI Remote API 擅长"操作"，"读"只能读到宿主参数级别的状态；工程里音符与和弦的完整数据仍以 MIDI 导出为准（`core/midi` 已在 M1 具备解析能力）。


### 5.2 已验证的环境事实

- Cubase 13：`D:\Production\Cubase 13\Cubase13.exe`
- Studio One 5：`D:\Production\Studio One 5\Studio One.exe`
- Cubase 13 用户数据目录：`C:\Users\bubbl\AppData\Roaming\Steinberg\Cubase 13_64`

- `cua-driver` **0.36.0** 已安装（`C:\Users\bubbl\AppData\Local\Programs\Cua\cua-driver\bin\`），插件 `cn.star.computer-use` 0.4.0 的 `list_apps` / `get_app_state` 已实测可用
- Cubase 13 中文界面（菜单：文件 / 编辑 / 媒体 / 运行控制 / 工作室 / 窗口 / 帮助）
- 本机无 MIDI 设备、无虚拟 MIDI 端口驱动

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Cubase 不导入 MIDI chord 事件 | 和弦轨缺失 | 已规划降级方案（纯音符轨 + 级数轨名）；实现阶段实机验证 |
| 诊断规则误判 | 学习者被误导 | 诊断只对可计算部分下判断；文案用"倾向"而非"错误"；每条诊断附证据（具体小节与数值） |
| 网页合成器与 Cubase 音色不一致 | 预期落差 | 关卡与导出说明中显式区分"参数语义"与"音色本身" |
| 内容编写量超出预期 | 工期过长 | 24 关分三阶段交付；先做阶段一 + 一个完整实战关（关 23）验证闭环，再批量补齐 |
| 参考曲分析准确率不足 | 关卡 24 体验差 | 降级为"给出候选结果让学习者选"，而非断言 |

## 1. 为什么要有这份文档

主设计规格（2026-10-20）解决的是「教什么、怎么教」——内容层已经很扎实：
27 关递进、记忆锚、诊断引擎、MIDI 骨架导出、Leitner 复习队列。

但**产品层**是空的。具体地说，动手写代码前查了一遍现状：

| 现状 | 位置 |
|---|---|
| `styles.css` 里 `animation` / `@keyframes` 命中 **0** | 没有任何动效 |
| `VoiceId` 里没有音效位，全库搜 `playCorrect` / `chime` 命中 0 | 答题没有声音反馈 |
| 关卡内答完题不显示对错，只弹一段 `explain` | `LessonFlow.tsx` 听辨步 |
| 184 处硬编码色值（`#ffd666` 出现 14 次、`#ff7875` 4 次） | 没有 token 层 |
| 选关只能靠顶部下拉框；`levelLocked()` 恒返回 false | 没有首页，也没有路径 |
| 文案字段只有 `explain` 一个 | 解析兼做错误提示 |

结论：**内容层是 Duolingo 级的，产品层是「能跑」级的**。这份文档补产品层。

## 2. 产品定位

### 2.1 借鉴什么

Duolingo 值得借鉴的不是它可爱，是三件事：

1. **清晰的路径导航** —— 「下一步做什么」永远只有一个答案
2. **即时的多感官反馈** —— 颜色、形状、声音、动效同时给出
3. **统一的语气人格** —— 每句文案都在同一个声音里

### 2.2 不借鉴什么

**不引入吉祥物。** Duolingo 的 Duo 会卖萌会嘲讽，那是消费级语言产品的选择。
Music-101 是给一个要做出自己作品的人用的专业工具，吉祥物会稀释内容层的分量。

反馈的人格化用**文案**实现，不靠角色形象。详见 §5。

### 2.3 本项目特有的优势

反馈音用音乐语汇，不用通用音效。这是学音乐的产品才有的奢侈：

- 答对 → 在**当前调的音阶上**弹一个上行音程
- 答错 → 低八度、闷掉的下行二度
- 过关 → 调内三和弦琶音

声音本身就在表达语义，不用文字解释。这条是本项目独有的，不能照搬 Duolingo。

## 3. 界面设计

### 3.1 设计 token（已实现）

**唯一出处**：`src/ui/theme.ts`。色板、圆角、动效时长都在那里定，
CSS 变量和 antd 主题读同一份常量。

| 组 | 内容 |
|---|---|
| `palette` | 底色、表面、文字三级、品牌金、和弦蓝、语义三色 |
| `overlays` | 半透明叠加层（分隔线、淡底） |
| `whiteScale` | 白色叠加层的完整梯度（w02 … w92） |
| `colorScales` | 各色相的透明度梯度（金/蓝/红/绿/青/紫） |
| `extras` | 无法归类的独立色（热力图四档、琴键深色、纸面色） |

**为什么要这么细**：教学图里到处要用不同深浅的白和彩。之前是直接写
`rgba(255,255,255,0.32)` 这种魔数——同一个深浅在图 A 里是 0.32、在图 B 里是 0.3，
肉眼看不出是俩值，但改色时要改几十处。收成梯度之后每种深浅都有固定名字。

**注入方式**：`main.tsx` 里 `tokenStylesheet()` 生成 `<style>` 注入到 `<head>`。
不用手写一份 CSS，是因为要保证 antd 主题和 CSS 变量读同一个来源——
各写一套是 UI 走样的头号原因。

**守卫**（`tests/ui/theme.test.ts`）：
- `styles.css` 里不许再出现写死的主色和语义色
- CSS 里引用的每个 `--m101-*` 都必须在 token 里定义过
  （引用未定义变量 → 浏览器当无效值丢弃 → 那条声明静默失效）

**已完成的迁移**：`styles.css` 里 184 处硬编码色值全部换成变量引用。

### 3.2 答题选项（已实现）

`src/ui/QuizOption.tsx` 自己实现而不用 antd 的 `Radio`，因为要三样 antd 给不了的东西：

1. **整块选项都能点** —— 不是只点小圆点
2. **选项能整体变色、整体做动效** —— 扫光、弹起、抖动
3. **每项旁边挂「▶ 听」按钮** —— 在 Radio 的 label 里塞按钮会跟选中行为打架

键盘可达性自己补齐：`role="radiogroup"` / `role="radio"`，
方向键切换并选中（`onKeyDown` 里 `ArrowUp/Down/Left/Right`），跟原生 radio 一致。

### 3.3 首页路径图（已实现）

这是「像不像产品」的第一印象。

**它是一条路，不是一格一格的菜单。** 区别在哪儿：格子告诉「有 27 个关」，
路告诉「你从这儿走到那儿」。所以节点横向摆动、纵向排开，连线是一条曲线。

三个设计决定：

1. **节点上写关卡标题和记忆锚口诀，不只写关号。**
   「第 14 关」只是个编号；「和声张力与解决」是他真正学过的东西。
   学习者认的是名字，不是编号。
2. **摆动周期是 3 个节点**：序列 0 → +幅 → -幅 → 0。
   三个一组正好左右交替一次，相邻节点错开约 0.87×幅——
   读起来是蛇形，不是「一列」（那样摆动就白做了）。
3. **当前关会呼吸，其余安静。** 呼吸只用 opacity，不动位置。

**节点四态**：

| 状态 | 判据 | 视觉 |
|---|---|---|
| `mastered` 已掌握 | 打过了并且过了 | 绿色徽标「已掌握」，安静地亮着 |
| `retry` 上次没过 | 最近一次尝试没过 | 红色描边 + 「上次没过」 |
| `new` 没做过 | — | 中性描边 |
| `current` 下一步 | **第一个没掌握的关** | 金色描边 + 光晕 + 呼吸 |

「当前关」的规则是第一个没掌握的关——不是「最后一关 + 1」，
所以中间跳关之后它会自动指向真正的下一步（跳过了 1、2、5 的话，当前关是 3）。

**阶段边界是断开的**。「地基 → 编曲 → 风格」是三次跳跃，看得见才对。
每个阶段内部摆得漂亮就够了，首尾不强制回中线。

**进度用关数不用百分比**：27 关的 8% 对学习者没有意义，「8 / 27 关」才有。

### 3.4 双模式导航（已实现）

以前是七个平级按钮并排——那不是导航，是功能清单。
它同时回答了七个问题，于是一个问题也没回答。

现在分成两种心智：

- **闯关模式**（默认落点）：路径图回答「接下来做什么」，是主线
- **工具模式**（随时可进）：乐理工作台 / 诊断 / 记忆点 / 复习 / 进度，是沙盒

关卡下拉保留在闯关模式里（快速跳转用），复习按钮带到期角标。
关卡内的按钮文案随位置变：路径图上叫「学习路径」，关卡里叫「返回路径」。

## 4. 动效设计

### 4.1 三条规矩（`src/ui/motion.css`）

1. **只动 `transform` 和 `opacity`** —— 动 `width`/`height`/`top` 会触发布局重排，
   一屏几十个元素一起动就掉帧
2. **时长和缓动只从 token 取** —— 只有三档（fast 140ms / base 220ms / slow 380ms），
   每处现编一个 137ms，累积起来就是「哪儿都不对劲」
3. **每个动效都要有 `prefers-reduced-motion` 降级** —— 这不是可选项。
   有些人（前庭功能障碍、注意力障碍）对动效敏感，页面动得太厉害会直接让人难受。
   浏览器会把这个偏好告诉站点，我们得接住。

### 4.2 动效只服务于两件事

- **因果**：告诉学习者「你刚才那一下发生了什么」
- **引导**：把注意力带到该去的地方

纯装饰的动效不做——它会稀释真正有意义的那几个。

### 4.3 已实现的动效

| 名称 | 时长 | 用途 |
|---|---|---|
| `m101-pop` | 220ms spring | 答对了：轻轻弹一下 |
| `m101-shake` | 220ms out | 答错了：左右晃两下，幅度 5px |
| `m101-sweep` | 380ms out | 答对了：正确项上扫过一道光 |
| `m101-rise` | 220ms out | 反馈面板从下往上浮 |
| `m101-stamp` | 380ms spring | 过关盖章：先放大再落定，最后微微一歪 |

`m101-breathe`（路径图当前节点的脉冲）随 P1 的路径图一起做。

### 4.4 反馈不能只靠颜色

颜色之外必须有形状：答对是 `✓` 绿底，答错是 `✗` 红底。
屏幕阅读器读不出图标，所以还有 `.sr-only` 的「答对了」/「答错了」文字。

色觉障碍用户看到的是：绿色 + 对勾 / 红色 + 叉号 + 抖动。
这是**三条独立通道**，任意一条失效都还能分辨。

## 5. 文案设计

### 5.1 现有文案的质量比 Duolingo 高

`"半音是隔壁，全音隔一个。"`（`level-02.ts:30`）、
`"记的时候不要去数黑键。直接看键盘"` —— 这些是真人写的钩子句，有画面感。

**千万别为了「游戏化」把它改成模板文案**，那是降级。

### 5.2 真正的问题是结构太薄（已修复）

`StageEar` 原来只有 `prompt / choices / correct / explain` 四个字段，
`explain` 一个字段兼任「解析」和「错误提示」两职。

看实际内容就明白问题：

```
explain: "C 到 C♯ 只隔一个键。C 到 D 隔了一个黑键，是全音。"
```

这句话**直接把答案说了**。学习者答错「C4 → D4」之后看到它，等于被告知「选 C♯」。

拆成三个（**已实现**）：

```ts
explain: string     // 解析：为什么是这个答案
wrongHint: string   // 答错时：引导方向，不给答案
encourage: string   // 答对时：一句跟这道题相关的反应
```

**178 道题全部补齐**（关 1–8 手写 64 道，关 9–27 走 `ear()` 模板 114 道）。

`wrongHint` 的写法有硬规矩：**给方法，不给答案**。

- ❌「E 到 F 是半音，再高一个半音到 F♯ 才是全音」—— 这就是 `explain`，说了答案
- ✅「从 E 往上找，找到第一个没有黑键隔开的位置。」

`encourage` 要**把刚做对的事再说一遍**，不是空泛的鼓励：

- ❌「太棒了！」
- ✅「对，挨着的两个键就是半音。」

**新字段是可选的**（`wrongHint?`），所以忘了写不会报错——只会悄悄退回
整关通用的记忆锚提示。守卫测试 `tests/lesson/ear-feedback.test.ts` 把这件事挡住：
每道题都必须有 `wrongHint` 和 `encourage`、不能是 `explain` 的复制、
长度在合理区间、不能出现正确项的文字、同一关里不能有重复的引导。

### 5.3 两级提示（已实现）

这是 P0 里最重要的一条教学决定：

- **第一次答错**：只给方向（这一关的记忆锚口诀），**不给答案**
- **第二次还错**：才亮出正确项和解析，并且这道题**锁死**

理由：第一次就报答案，学习者记住的是「那一题选了 B」，
不是「怎么判断它是 B」。这跟复习队列（Leitner 盒）是同一个道理：答错了就掉档。

锁死的理由：答案已经写在脸上，再选一遍不算学会。锁死之后这道题计为答错，
学习者知道自己没掌握，可以去复习。

### 5.4 反馈文案轮换（已实现）

`src/core/lesson/copy.ts`。一句「正确。」重复三百遍，耳朵会先于脑子关掉。

按题号轮换（不是随机——刷新页面顺序不变，学习者能预期第几题听到哪句）：

- 答对：`对了。` `就是这个。` `抓得准。` `听出来了。` `稳。`
- 答错：`再想想。` `差一点，再来。` `不对，再试一次。` `换个角度听。`

### 5.5 产品人格

**不设吉祥物，但要有统一的声音。** 判据是三条：

1. **具体** —— 说「半音是隔壁」而不是「半音是相邻的两个键」
2. **给方向不给答案** —— 报答案是放弃教他
3. **口语但不油** —— 第二人称、断言式，几乎不用感叹号

## 6. 声音反馈

### 6.1 三种音效（已实现）

`src/core/audio/sfx.ts` 是纯函数（不碰 AudioContext），单测直接断言音程关系。

| cue | 形状 | 音色 | 语义 |
|---|---|---|---|
| `correct` | 调内三度，上行 | pluck（拨弦，明亮） | 上行 = 对了 |
| `wrong` | 下行二度，低八度 | bass（低通，闷） | 下行 = 不对 |
| `pass` | 调内三和弦琶音，末音落八度 | pluck | 展开 = 完成了 |

**音程关系是设计意图，断言的是关系不是具体音高**：
关系对了，具体音高随便换都不影响设计意图。

**跟着关卡的调走**：第 3 关的「对了」那一声就在第 3 关的调里。
复习页抽的是各关的题，用题目所属关卡的调。

### 6.2 关键约束：音效必须在用户手势的同步链路里触发

浏览器的自动播放策略规定 AudioContext 必须在用户手势内 resume。
如果把播音放到 `useEffect` 里（React 提交后的异步路径），第一次答题就会静音——
这正是很多网页「点了按钮没声音」的原因。

所以 `src/ui/useFeedbackSfx.ts` 返回的是**普通函数**，调用方在 `onClick` 里直接调，
不经过任何异步跳转。`resume()` 不 await（它本身就是解锁动作）。

### 6.3 独立总线

反馈音走自己的 `GainNode`（增益 0.7），不直接连 master。
它是提示，不是内容——抢了注意力就本末倒置，而且要能单独压低。

## 9. 非目标

- **不做吉祥物** —— 见 §2.2
- **不做纯装饰动效** —— 见 §4.2
- **不改评分口径** —— 听辨阈值（`earPass`）、诊断 severity 全部不动。
  反馈只改「怎么呈现」，不改「怎么算」
- **不做移动端专门优化** —— 桌面优先，沿用主设计规格
- **不引入第三方音频素材** —— 三种音效全是 Web Audio 实时合成，零外部请求

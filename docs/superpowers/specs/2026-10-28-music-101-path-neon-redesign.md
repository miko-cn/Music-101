## 1. 为什么重做

现有路径图（P1）在规则上是对的——「下一步只有一个答案」、节点写标题与口诀、四态清晰——但**气质偏工程稿**：蛇形轨道信息密度高、视觉像调试面板，不像 kawaii / future bass 产品首页。

本次**推翻视觉与编排气质**，保留路径语义与双模式导航。

### 1.1 已确认的方向

| 项 | 决定 |
|---|---|
| 核心问题 | 看起来丑、不像产品；整体气质重做 |
| 气质 | 贴合曲风：kawaii / future bass，有一点霓虹和活泼 |
| 布局隐喻 | **A 霓虹航道**：保留「一条路」，重做颜色 / 卡片 / 动效 |
| 吉祥物 | 要；**Miko**——耳机霓虹猫，尾巴像电平条；**16×16 粗像素** |
| 霓虹强度 | **克制到产品级**：像正式上线产品，不像 demo；光晕点到为止，禁止彩虹花屏、禁止大面积发光 |
| 示意图反馈（2026-10-28） | 主页再暗、更第一性原理（先看清下一步）；Miko 可用，但 **Idle 禁止多手/鬼影肢体** |

## 2. 目标与非目标

### 2.1 目标

1. 打开闯关模式首页，**3 秒内**看出「下一关是什么、点哪里开始」。
2. 视觉读得出 future bass / kawaii：深色舞台、少量霓虹、活泼但不吵。
3. 完整 27 关仍可扫完，阶段边界仍看得见。
4. Miko 增加亲和力，不抢主按钮、不嘲讽用户。

### 2.2 非目标

- 不改关卡内容、进度 schema、掌握判定规则。
- 不把工具模式（乐理 / 诊断 / 记忆 / 复习 / 进度）并进路径页。
- 不做账号、后端、真实 3D / Lottie 大片；像素精灵用静态帧 + CSS 切换姿势即可。
- 不引入百分比进度文案（继续用 `已掌握数 / 总关数`）。

## 3. 信息结构

首页仍只答一个问题：**接下来做什么？**

```
┌─────────────────────────────────────────────┐
│  下一关大卡（主 CTA）          │  Miko 待机  │
│  第 N 关 · 标题 · 口诀 · n/27 · [开始这一关] │
└─────────────────────────────────────────────┘
┌ 阶段 01 地基 ─────────────────────────────┐
│   ○──霓虹细线──○──○──…（蛇形略收）        │
└──────────────────────────────────────────┘
┌ 阶段 02 编曲 ─────────────────────────────┐
│   …                                        │
└──────────────────────────────────────────┘
┌ 阶段 03 风格 ─────────────────────────────┐
│   …                                        │
└──────────────────────────────────────────┘
```

### 3.1 顶区「下一关」卡

- 文案层级：kicker「接下来」/「全部掌握」→ 标题「第 N 关 · {title}」→ 口诀 hook → 进度 Tag `done / total` → 主按钮「开始这一关」或「再看一遍」。
- 视觉：略抬起的玻璃卡 + **单色系**霓虹描边（全站统一一种主强调色，另一色只做辅线）。
- 当前关数据仍来自 `pathStates`：第一个未掌握关；全掌握时指向最后一关并改文案。

### 3.2 阶段航道

- 三阶段断开，标题保留 `01 / 02 / 03` + 阶段名。
- 节点仍由 `layoutPath` 驱动，**幅度略收**（实现时下调 `NODE_AMPLITUDE`，以相邻节点错开仍可读、又不像甩来甩去为准）。
- 阶段辅色克制区分：地基偏青、编曲偏紫、风格偏粉——**只染连线与阶段标签**，不把整段背景刷满。

### 3.3 节点四态（语义不变）

| 状态 | 判据 | 视觉（克制霓虹） |
|---|---|---|
| `mastered` | 已掌握 | 青绿小徽标，描边弱 |
| `retry` | 上次没过且未掌握 | 玫红细描边 +「上次没过」 |
| `new` | 未做 | 中性玻璃描边 |
| `current` | 第一个未掌握 | 主强调色柔光；**仅 opacity 呼吸** |

节点文案：关标题 + 记忆锚口诀；关号可作次级。

### 3.4 导航

双模式不变：闯关默认路径图；工具模式旁路。关卡内「返回路径」文案不变。

## 4. 吉祥物 Miko

### 4.1 形象

- 名字：**Miko**
- 造型：戴耳机的猫；尾巴表现为短电平条（2–3 格像素）。
- 画风：**16×16 粗像素**，显示时 **整数倍放大**（建议 4× → 64 CSS px），`image-rendering: pixelated`，禁止模糊缩放。
- 调色：与路径主强调色同系，轮廓清晰，在深色底上可读。
- **解剖约束（硬）**：任何姿势最多两只前爪/手臂；Idle **禁止**多手、重叠鬼影肢、多出来的袖子。Idle 优先「坐姿双爪并拢」或「半身头肩 + 耳机」以免肢体糊成一团。精灵须手绘/逐帧校对，不直接用未校对的生成图上线。

### 4.2 出现位置

| 场景 | 行为 |
|---|---|
| 路径首页「下一关」卡旁 | 待机姿势（轻微两帧呼吸可选，须尊重减动效） |
| 用户点「开始这一关」 | 可切「指向 / 加油」一帧，不挡按钮 |
| 过关盖章时 | 庆祝姿势一帧（蹦一下用 transform） |
| 其它路径节点 / 工具页 | **默认不出现** |
| 文案 | **不说话、不嘲讽**；反馈人格仍用现有文案与音效 |

资源建议：`src/ui/miko/` 下若干 PNG 或内联像素 sprite；姿势至少：`idle`、`cheer`（可选 `point`）。

## 5. 视觉与动效（产品级克制）

气质标准：**第一性原理**——用户 3 秒只应看到「下一关是什么 / 点哪里开始」。装饰服务于这个目标；任何让页面像概念 demo、赛博橱窗的处理都删除。

### 5.1 色与材质

- 页底：近黑或炭灰（如 `#0b0d12`），最多极弱冷色洗染；禁止紫雾铺满。
- 霓虹：**细线、低发光**（连线 1px + 很低透明度外发光）；一屏强发光元素 ≤ 下一关主按钮 + 当前节点。
- 卡片：深色表面 + 细中性描边为主；强调色描边只给「下一关」与 `current`。
- 主强调色全页只主推一种（从 `theme.ts` 扩展）。默认偏青，粉只用在阶段辅线或 Miko 小高光。

### 5.2 动效规矩（继承产品规格 §4）

1. 只动 `transform` / `opacity`。
2. 时长取 motion token（fast / base / slow）。
3. 每个动效有 `prefers-reduced-motion` 降级（呼吸与 Miko 帧动画关掉）。
4. 当前关呼吸保留；不做整页视差、不做节点乱跳。

### 5.3 与旧版差异摘要

| 旧 P1 | 本设计 |
|---|---|
| 工程感蛇形 + 中性金 | 克制霓虹航道 + 阶段辅色 |
| 无角色 | 像素 Miko 仅顶区 / 过关 |
| 幅度偏大 | 幅度略收，更易扫 |

## 6. 实现边界

- 主要改：`PathMap.tsx`、路径相关 CSS、`path-layout.ts` 幅度常量、`theme.ts` token 扩展、新增 Miko 资源与小组件。
- 尽量不改：`path.ts` 状态规则、`progress` schema、Lesson 内容。
- 测试：保留 `tests/lesson/path.test.ts` 语义；布局测试若幅度常量变更则更新期望值；补减动效降级的轻量测（若值得）。
- 验收：浏览器截图——顶区下一关 + Miko；三阶段航道；当前关柔光；减动效开启时无呼吸。

---

## 7. 开放实现细节（不阻塞规格）

1. 主强调色最终选金粉还是青粉：实现时出两版截图可再拍板，默认偏青粉。
2. `NODE_AMPLITUDE` 精确像素：以「相邻错开仍可见弧线、一屏不晕」为准调。
3. Miko 是否要第二套色板适配 `retry`：首版不做。

---

## 8. 成功标准

1. 用户主观：路径首页「像产品」而不是调试稿。
2. 「开始这一关」仍是视觉第一焦点；Miko 不压过 CTA。
3. 霓虹有氛围但不花：一屏同时发光的强元素 ≤ 下一关卡 + 当前节点 + 当前段连线。
4. 现有路径单测语义全绿；`prefers-reduced-motion` 下调掉呼吸与精灵帧动画。
